## 为什么拆成四个阶段

生活模块是**三个互相独立的数据域**（健身 / 饮食 / 游戏娱乐），彼此没有数据依赖，各自都能单独产出可运行、可验收的成果。第四个阶段把它们接到「今天」页卡片上，是 M4 唯一的跨模块工作。

拆法与 M3 一致：每阶段 = 一次迁移 + 一个数据层 + 一组纯函数 + 一个 IPC 命名空间 + 一个 store + 页面，最后统一验收。

## 数据模型（设计文档 §7.5–7.7 + 必要偏差）

### 健身（v6）

| 表 | 列 | 说明 |
|---|---|---|
| `workout_plans` | `id, name, schedule, created_at, updated_at` | `schedule` 为 JSON，形如 `{"1":"胸","2":"背"}`，键是 ISO 星期（1=周一…7=周日） |
| `workout_logs` | `id, plan_id, date, content, created_at, updated_at` | `content` 为 JSON 数组 `[{name, weight, sets, reps}]`；`plan_id` 可空并 `ON DELETE SET NULL` |
| `body_metrics` | `id, date UNIQUE, weight, body_fat, created_at, updated_at` | 每天一条，`body_fat` 可空 |

**偏差**：设计文档的 `schedule` 示例用中文键（`{"周一":"胸"}`）。改用 ISO 数字键，避免依赖中文字符串做逻辑判断——展示层再映射为「周一」。

### 饮食（v7）

| 表 | 列 | 说明 |
|---|---|---|
| `meals` | `id, date, type, items, created_at, updated_at` | `type ∈ breakfast/lunch/dinner/snack`；`items` 为 JSON 数组 `[{name, calories, protein, carbs, fat}]` |
| `meal_plans` | `id, date, type, content, created_at, updated_at` | 计划内容为文本；`(date, type)` 唯一 |

### 游戏娱乐（v8）

| 表 | 列 | 说明 |
|---|---|---|
| `plays` | `id, game, date, minutes, created_at` | 一条 = 一次游玩 |
| `wishlist` | `id, name, platform, priority, created_at, updated_at` | `priority ∈ low/mid/high`（复用既有 `Priority`） |
| `media` | `id, title, type, status, rating, comment, date, created_at, updated_at` | `type ∈ movie/series/book`；`status ∈ planned/doing/done`；`rating ∈ 0..5` |

## 全局约束（与 M1–M3 一致）

- 数据目录 `%APPDATA%\LifeOS\`；渲染进程禁止直接访问数据库与文件系统
- 多步写入包在事务中，失败回滚
- **不得修改已发布的 v1–v5 迁移**，M4 新增 v6 / v7 / v8
- 深色色板与模块色：健身红 `#e74c3c`、饮食琥珀 `#f39c12`、游戏娱乐紫 `#a06ee1`
- 日期 `YYYY-MM-DD`，日期时间 `YYYY-MM-DD HH:MM`
- 提交前固定顺序：`npm test` → `npm run typecheck` → commit
- 起点基线：32 个测试文件 / 528 用例全绿，`typecheck` 0 错误

## 风险与对策

| 风险 | 对策 |
|---|---|
| JSON 列（`schedule` / `content` / `items`）读写容易出脏数据 | 统一走"解析→校验→序列化"的纯函数，坏数据回退到空数组/空对象（沿用 `parseTags` 的做法），并有单测 |
| 体重曲线涉及 SVG 坐标计算，容易画歪 | 把「值 → 坐标」抽成纯函数并单测（含等值、单点、极值跨度） |
| 一周安排的键类型不统一（中文/数字） | 锁死 ISO 数字键，展示层映射；迁移测试覆盖 |
| 每日合计口径（热量/蛋白/碳水/脂肪）易与展示不一致 | 合计只在纯函数里算，数据层不做聚合，界面不重复实现 |
| 新增三个迁移提升了"版本号写死"的风险 | 复测既有迁移测试全部引用 `LATEST_VERSION`（M3 已统一） |
