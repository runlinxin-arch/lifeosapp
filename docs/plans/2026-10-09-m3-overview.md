## 为什么拆成四个阶段

M3 是三个**互相独立的业务子系统**加一条横切关注点（长期任务标记入口）。按 writing-plans 的规模判定，它们应当拆成独立计划，每个都能独立产出可运行、可验收的软件：

| 阶段 | 内容 | 表 | 详细计划 |
|---|---|---|---|
| **M3-1** | 共享底座 + 自我学习 | `learn_items` / `learn_notes` / `learn_sessions` | [2026-10-09-m3-1-learning.md](./2026-10-09-m3-1-learning.md) |
| **M3-2** | 开发模块 | `projects` / `dev_tasks` / `bugs` / `snippets` / `tech_notes` / `dev_sessions` | 开工前产出 |
| **M3-3** | 设计灵感 | `inspiration_boards` / `inspirations` | 开工前产出 |
| **M3-4** | 「今天」页卡片接线 | — | 开工前产出 |

依赖关系：**M3-1 先做**，它交付的共享底座（页面注册、来源标记接线、通用列表/进度/标签组件）被 M3-2/M3-3 复用；M3-4 依赖前三者。

```
M3-1（底座 + 学习）──┬──► M3-2（开发）──┐
                     └──► M3-3（灵感）──┴──► M3-4（今天页卡片）
```

## 全局约束（与 M1/M2 一致，任何任务都适用）

- 数据目录 `%APPDATA%\LifeOS\`（`app.db` + `images/` + `backups/`）
- 渲染进程禁止直接访问数据库与文件系统；一切经 IPC 到主进程
- 多步写入必须包在 SQLite 事务中
- 深色色板：底色 `#1e1f24`、卡片 `#26272e`、描边 `#3a3b45`、强调 `#7c8cff`、正文 `#e4e4e7`、次要 `#8b8d98`
- 模块色：学习 `#4ade80`、开发 `#3498db`、灵感 `#e879c9`
- 日期 `YYYY-MM-DD`、日期时间 `YYYY-MM-DD HH:MM`（本地时区，字典序即时序）
- 数据库驱动锁定 `node:sqlite`，**不得引入 better-sqlite3 或任何原生编译依赖**
- 迁移必须走 `user_version` 机制（M2 已建立），新表一律新增一个迁移版本，**不得修改已发布的迁移**
- 提交前固定顺序：`npm test` → `npm run typecheck` → commit
- 每完成一个可独立验收的任务立即 commit

## 验收总锚点（PRD 8.6）

1. **自我学习**：学习项 CRUD、进度更新、笔记增删改、学习计时计入统计、连续天数正确累计
2. **开发**：项目 CRUD；看板卡片跨列拖拽且位置持久；Bug 状态流转；计时按项目汇总；代码片段按标签/关键词搜到；技术笔记可关联项目
3. **设计灵感**：捕获弹窗支持贴图/文字/链接三种方式；图片瀑布流展示；精选筛选、标签筛选、搜索可用；画板创建与归入正常；删除灵感时本地图片文件同步删除

## 非目标（M3 不做）

- 学习项/项目的导入导出（M5）
- 灵感视频收藏、灵感状态流转（PRD 第 7 章明确不做）
- 开发模块的 Git 集成
- 任何联网功能（网站风格模仿属 M5 且是唯一联网例外）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 图片存取的路径穿越（灵感图片按 UUID 命名） | 主进程只接受 UUID 文件名，落盘路径由主进程拼接，渲染端永不给路径 |
| 看板拖拽在 Electron 下的兼容性 | 与 M2 一致：HTML5 拖拽为主，同时提供「移动到…」菜单作为等价路径，验收不依赖拖拽 |
| 计时器跨零点/应用重启后的悬挂会话 | `dev_sessions` / `learn_sessions` 只记录已结束的会话；应用启动时把未结束的会话按最后心跳截断（M3-2 处理） |
| 三模块 UI 复用度 | M3-1 先沉淀通用组件（列表项、进度条、标签输入、空态），后续阶段复用 |
