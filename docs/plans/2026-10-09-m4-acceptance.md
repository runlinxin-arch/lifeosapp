## 六、与设计文档的偏差汇总（需 M5 回写设计文档）

| # | 偏差 | 原因 |
|---|---|---|
| 1 | `workout_plans.schedule` 键改为 ISO 数字（`{"1":"胸"}`） | 避免中文字符串参与逻辑判断 |
| 2 | `workout_logs.plan_id` 用 `ON DELETE SET NULL` | 删计划后历史打卡保留 |
| 3 | `body_metrics.date` 加 `UNIQUE` + upsert | 每天一条，避免口径歧义 |
| 4 | `meals` / `meal_plans` 的 `(date,type)` 唯一 + upsert | 每天每餐一条记录 |
| 5 | 饮食**不做**热量进度条与目标值 | PRD L224 把饮食目标列为未来扩展，L109 要求"纯数值展示" |
| 6 | 新增 `WorkoutHistory`（打卡历史） | PRD 4.5「保留历史」缺可见入口 |
| 7 | `BodyMetricDialog` 合并进 `BodyTrend.tsx` | 弹窗与卡片强耦合，拆开需传 8 个 props |
| 8 | `plays.minutes` 校验 1–1440 整数 | 防止误填造出天文数字总时长 |
| 9 | `media.rating` 为 0–5 整数，0 = 未评分 | 与五星组件空态一致 |
| 10 | 按游戏聚合大小写敏感，不隐式合并 | 不改写用户输入的游戏名 |
| 11 | **游戏娱乐页签调整为「游玩记录 \| 影视 \| 书籍」** | 用户 2026-10-09 复核后要求"把影视和书分开" |
| 12 | 游玩统计**默认区间为「本周」**，可切本月/全部 | 工作台以"今天"为中心，本周是更常用的复盘窗口（用户要求加区间后定的默认值） |
| 13 | **移除愿望单功能**（PRD 4.7 / 8.7.3 的愿望单条目不再实现） | 用户 2026-10-09 明确要求；`wishlist` 表与 v8 迁移保留未动，数据未删 |

## 七、仍待人工确认（汇总）

1. **界面观感**：截图 `docs/acceptance-shots/31~37`、`39~41` 共 10 张，覆盖三个模块与「今天」页卡片。
2. **体重/体脂双线呈现**：各自独立归一化，只有两个数据点时两条线必然重合（M4-1 记录）。
3. **饮食计划横条密度**：展示未来 14 天，是否合适（可改 7 天 + 翻页）。
4. **饮食"周模板"**：目前"提前规划某周的餐食"通过逐天编排满足，是否需要一次性套用一周模板。
5. **游玩统计默认区间**：现为「本周」（可一键切「全部」）；若不希望默认收窄，改一处初始值即可。
6. **筛选入口重复**：游玩记录同时提供"游戏下拉"与"点聚合行筛选"两个入口，是否只保留其一。
7. **`wishlist` 表去留**：功能已移除但表与数据保留未动；是否在 M5 用 v9 迁移删除该表。

> 已由用户 2026-10-09 复核并要求实现、且已完成的三项：游玩按周/月统计、影视与书籍分开、移除愿望单（见 M4-3 验收记录第四节）。
