## 五、设计决定

1. **渲染进程永不接触文件路径**：只发送 `ArrayBuffer` + MIME；文件名由主进程用 `randomUUID()` 生成。路径穿越防护做了两层（白名单正则 + 解析后目录归属校验），并用**真实协议请求**验证。
2. **先提交事务、再删文件**：避免"文件没了但记录还在"。删文件失败不算错（文件已不存在是正常情况）。
3. **落库失败回收文件**：图片先写盘、再落库；落库失败时删除刚写入的文件，不留孤儿。存储以 `ImageStore` 接口注入，因此该编排可在**不接触真实文件系统**的前提下单测。
4. **瀑布流不依赖 DOM 测量**：高度估算 + 贪心最短列，纯函数可单测，结果可复现。
5. **`LatestGuard` 竞态守卫**：并发刷新时只接受最新请求的结果。

## 六、过程中的问题与修正

### 1. 真实的跨模块竞态（已修复）

`load()` 与写操作后的 `refreshAll()` 会并发发起同名请求；**先发起的慢响应若后到达，会用旧列表覆盖刚保存的数据**，表现为"刚保存的记录不显示，切走再切回又出现"。

这是**学习、开发、灵感三个 store 共有**的隐患，此前未暴露只因 E2E 恰好都等到了 `load()` 完成。已抽出 `LatestGuard` 并统一修复，测试包含真实时序用例（慢请求后到必须被丢弃）。

### 2. 两次测试脚本自身的缺陷（非产品缺陷）

- **选择器歧义（一）**：页面搜索框 placeholder「搜索文字 / 链接 / **标签**」含「标签」，脚本用 `placeholder.includes('标签')` 全局查找时先命中它，把标签写进了筛选条件 → 列表被过滤成 0 条。修法：弹窗内选择器一律限定在弹窗内。
- **选择器歧义（二）**：用「div 含文本且按钮数 ≥2」找卡片时命中外层列容器，⭐ 点到了别的卡片。修法：给卡片加 `data-insp-card` 稳定标识。

> 两次都是**先加插桩拿到证据、确认是脚本问题**，再改脚本；没有通过放宽断言来"通过"。

### 3. 仍未消除的调试钩子

页面根节点保留了 `data-insp-filter` / `data-insp-items` / `data-insp-tags` 三个属性用于 E2E 观测，卡片保留了 `data-insp-card`。它们不影响功能，但属于测试专用标记，已在此备案。

## 六、验收后的人工反馈与修复（2026-10-09）

用户在人工验证拖拽手感与粘贴功能时提出两点体验问题，修复过程中又发现一处真实缺陷。

### 6.1 看板落点要求精细操作（体验问题）

**现象**：跨列/列内插入需要瞄准卡片之间 8px 高的窄缝，"十分仔细的精细操作"才能命中。

**根因**：投放区是卡片之间的窄条，悬停在卡片本体上不触发任何落点计算。

**修复**：改为**整列都是投放区**。新增纯函数 `dropIndexFromY(cards, clientY)`——从上往下找第一张"中线在指针下方"的卡片，插到它前面；都不满足则插到末尾。
- 目标区域从 8px 变为整列
- 落点指示条常驻文档流（6px 占位），激活时内部画出 3px 蓝条，**不引起布局抖动**
- 9 个新用例覆盖：上半/下半、恰好等于中线、列顶之上、空列、单卡、越界夹紧

### 6.2 「粘贴」与「选择图片」混在一起（体验问题）

**现象**：贴图只有一个虚线框，点击即选文件，"粘贴"只是文案提示，不是可操作的分支。

**修复**：
- 贴图区块改为**两个并列分支**：「📁 选择图片」（点击选择 / 拖入文件）与「📋 粘贴」（读取剪贴板）
- 粘贴改走**主进程剪贴板**，不再依赖键盘事件与焦点；Ctrl+V 快捷键保留
- 出现预览后显示尺寸与格式，并提供「重新选择」

### 6.3 捕获弹窗的图片预览从未显示过（真实缺陷）

**发现过程**：为 6.2 写的断言要求预览 `<img>` 的 `naturalWidth > 0`（而不是只检查元素存在），结果失败——而保存后的瀑布流图片 `naturalWidth` 是 480，说明图片本身没问题，是**预览**坏了。

**根因**：
```
CSP: img-src 'self' data: lifeos-image:     ← 不含 blob:
```
预览用的是 `URL.createObjectURL()` 产生的 `blob:` URL，被 CSP 拦截。因此**「选择图片」与「粘贴」两条路径的预览都从未显示过**。

**为何此前未发现**：M3-3 的 E2E 对预览的断言是「元素存在」，而 CSP 拦截不会移除元素——它照常留在 DOM 里，只是永远不显示。这正是"断言太弱"的典型后果。

**修复**：CSP 的 `img-src` 增加 `blob:`。

### 6.4 附带修正

`insp:readClipboardImage` 的实现按 **Electron 44 的真实 API** 重写：同步的 `readImage()` 已不存在，现为 W3C 风格的 `read(): Promise<ClipboardItem[]>` + `item.getType(type)`。类型检查拦下了这个错误（否则会在运行时才崩）。
