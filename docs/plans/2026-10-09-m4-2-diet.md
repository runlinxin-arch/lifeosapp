# M4-2 饮食模块 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付「饮食」模块：三餐+加餐打卡（每餐可录入多食物及热量/蛋白/碳水/脂肪）、每日摄入合计面板、可对未来日期编排的饮食计划横条。对应 PRD 4.6 与 8.7.2、界面 PRD L109。

**Architecture:** 延续 M1–M4-1 的分层。新增两张表以迁移 v7 落地；食物数组以 JSON 列存储，读写统一走「解析 → 校验 → 序列化」纯函数（坏数据回退空数组，不炸界面）；营养合计与日期序列全部是纯函数，界面只做展示。

**Tech Stack:** Electron 44 + electron-vite + React 18 + TypeScript + Tailwind + Zustand + `node:sqlite` + Vitest

## Global Constraints

- 数据目录 `%APPDATA%\LifeOS\`；渲染进程禁止直接访问数据库与文件系统
- 多步写入必须包在事务中，失败回滚
- 深色色板：底色 `#1e1f24`、卡片 `#26272e`、描边 `#3a3b45`、强调 `#7c8cff`、正文 `#e4e4e7`、次要 `#8b8d98`；**饮食模块色琥珀 `#f39c12`**
- 日期 `YYYY-MM-DD`；餐次枚举固定为 `breakfast | lunch | dinner | snack`
- **不得修改已发布的 v1–v6 迁移**，本次新增 v7
- 提交前固定顺序：`npm test` → `npm run typecheck` → commit
- 起点基线：35 个测试文件 / 618 用例全绿，`typecheck` 0 错误
- 复用：`assertNonEmpty` / `assertDateStr` / `assertDateRange`、`formatIpcError`、`LatestGuard`、`fitnessContent` 的容错思路、`dates.ts` 的 `addDays` / `todayStr` / `formatCn`

## 与设计文档的偏差（需在 M5 回写）

1. `meals` 增加 `(date, type)` **唯一约束**：每天每餐只保留一条记录，写入走 upsert（与 `body_metrics` 同思路）——避免"两顿早餐"造成合计口径歧义
2. `meal_plans` 的 `(date, type)` 同样唯一；`content` 为**纯文本**（设计文档写"文本/JSON"，取更简单的文本）
3. 设计文档 5.7 提到「热量进度条（vs 参考值）」，但 PRD L224 把**饮食目标列为未来扩展**、PRD L109 明确「纯数值展示」——因此**不做进度条与目标值**，只显示合计数值

### Task 2: 营养纯函数（TDD）

**Files:**
- Create: `src/shared/dietContent.ts`、`src/shared/dietStats.ts`
- Test: `tests/dietContent.test.ts`、`tests/dietStats.test.ts`

**Interfaces:**
- Produces（`@shared/dietContent`）：
  - `MEAL_TYPES: MealType[]`（固定顺序 早/午/晚/加餐）
  - `MEAL_LABELS: Record<MealType, string>`
  - `isMealType(v: unknown): v is MealType`
  - `parseMealItems(raw: string): MealItem[]`
  - `normalizeMealItems(input: MealItem[] | undefined): MealItem[]`
  - `mealItemsToJson(items: MealItem[]): string`
- Produces（`@shared/dietStats`）：
  - `sumNutrition(items: MealItem[]): Nutrition`
  - `dayNutrition(meals: Meal[], date: string): Nutrition`
  - `nutritionByMeal(meals: Meal[], date: string): Record<MealType, Nutrition>`
  - `mealByType(meals: Meal[], date: string, type: MealType): Meal | null`
  - `planText(plans: MealPlan[], date: string, type: MealType): string`
  - `recordedCount(meals: Meal[], date: string): number`
  - `plannedCount(plans: MealPlan[], date: string): number`
  - `upcomingDays(from: string, n: number): string[]`

**锁定的行为契约：**

*JSON 列*
1. `parseMealItems`：坏 JSON / 非数组 → `[]`；`name` 是字符串且去空白非空；四项营养都是**有限数且 ≥0**；任一不满足即丢弃该项（不整体失败）；允许全 0（白水也是合法条目）
2. `normalizeMealItems`：`name` 去空白且非空（否则丢弃该项）；四项营养**修正**为 ≥0 的有限数，四舍五入到 1 位小数

*统计*
3. `sumNutrition`：四项分别求和，**结果四舍五入到 1 位小数**（抹平 `0.1 + 0.2` 浮点噪声）；空数组 → 全 0
4. `dayNutrition`：只累计 `date` 等于当天的记录
5. `nutritionByMeal`：**总是返回四个键**，未记录的餐次为零值
6. `mealByType`：命中返回该记录，否则 `null`
7. `planText`：命中返回 `content`，否则空串
8. `recordedCount` / `plannedCount`：当天已记录的餐次数 / 已编排的计划数
9. `upcomingDays(from, n)`：返回从 `from` 起连续 n 天（**含 `from`**）；`n ≤ 0` → `[]`；跨月跨年正确

  sumNutrition, dayNutrition, nutritionByMeal, mealByType, planText,
  recordedCount, plannedCount, upcomingDays

import type { MealItem, Meal, MealPlan, MealType } from '../src/shared/types'

const food = (name: string, calories: number, protein = 0, carbs = 0, fat = 0): MealItem =>
  ({ name, calories, protein, carbs, fat })
const meal = (date: string, type: MealType, items: MealItem[] = []): Meal =>
  ({ id: 1, date, type, items, created_at: '', updated_at: '' })
const plan = (date: string, type: MealType, content: string): MealPlan =>
  ({ id: 1, date, type, content, created_at: '', updated_at: '' })

describe('sumNutrition', () => {
  it('四项分别求和', () => {
    expect(sumNutrition([food('a', 100, 10, 20, 5), food('b', 200, 20, 30, 10)]))
      .toEqual({ calories: 300, protein: 30, carbs: 50, fat: 15 })
  })
  it('空数组全零', () => {
    expect(sumNutrition([])).toEqual({ calories: 0, protein: 0, carbs: 0, fat: 0 })
  })
  it('浮点噪声被抹平（0.1 + 0.2 = 0.3）', () => {
    expect(sumNutrition([food('a', 0, 0.1), food('b', 0, 0.2)]).protein).toBe(0.3)
  })
})

describe('dayNutrition', () => {
  it('只累计当天', () => {
    const meals = [
      meal('2026-10-09', 'breakfast', [food('燕麦', 300, 10, 40, 8)]),

  })
  it('无记录全零', () => {
    expect(dayNutrition([], '2026-10-09')).toEqual({ calories: 0, protein: 0, carbs: 0, fat: 0 })
  })
  it('多餐累加', () => {
    const meals = [
      meal('2026-10-09', 'breakfast', [food('a', 300)]),
      meal('2026-10-09', 'lunch', [food('b', 700)])

  })

  - `listMeals(db, from?, to?): Meal[]`（`date DESC, id ASC`）
  - `getMeal(db, date, type): Meal | null`
  - `upsertMeal(db, input: MealInput): Meal`（同日同餐覆盖）
  - `deleteMeal(db, id): void`
  - `listPlans(db, from?, to?): MealPlan[]`（`date DESC, id ASC`）
  - `getPlan(db, date, type): MealPlan | null`
  - `upsertMealPlan(db, input: MealPlanInput): MealPlan`（同日同餐覆盖）
  - `deletePlan(db, id): void`

**锁定的行为契约：**
1. `type` 必须是四个枚举之一，否则抛 `餐次不合法`
2. `date` 必须是合法 `YYYY-MM-DD`（复用 `assertDateStr`），**允许未来日期**（为「提前编排」服务）
3. `items` 经 `normalizeMealItems` 后入库；**允许空数组**（只打卡"这顿吃了"）
4. `upsertMeal` 同一天同一餐**覆盖**而非新增（配合 `(date,type)` 唯一索引）
5. `upsertMealPlan` 的 `content` 去首尾空白后**不能为空**（清空计划由界面调用 `deletePlan`）
6. `getMeal` / `getPlan` 未命中返回 `null`
